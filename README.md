# mysh — учебный командный интерпретатор

Курсовой проект по ТЗ **«Разработка командного интерпретатора (shell), v0.1»**.
Автор: **Сарсенбекова Дария**, студентка КФМГУ, 2 курс, ВМК.

Проект на C23 для Linux/POSIX: лексер → рекурсивный парсер → AST → исполнитель.
Для исполнения используются `fork`, `execve`, `pipe`, `dup2`, `waitpid`.
Внешний shell для разбора команд не используется.

**Статус:** в Ubuntu WSL выполнены сборки GCC 15 и Clang 21 на C23 с
`-Wall -Wextra -Wpedantic -Werror`, пройдены функциональные и PTY-тесты на C.
Проверки памяти и ограничения подробно описаны в отчёте.
Список ограничений и отклонений приведён в [report.md](report.md).

## Сборка

Нужны Linux, GNU Make и GCC 14+ либо Clang 18+ с поддержкой `-std=c23`.
Для тестов нужны bash, стандартные Linux-утилиты и системная библиотека `libutil`
для псевдотерминала; для проверки памяти — Valgrind. Python не требуется.

```sh
make CC=gcc
./mysh
```

Альтернативная сборка:

```sh
make clean
make CC=clang
```

Если системный `gcc` старее, укажите установленный современный компилятор,
например `make CC=gcc-14`. Makefile намеренно не переключается молча на C17.
Нативная сборка для Windows не поддерживается: нужны Linux или WSL.

## Запуск

```sh
./mysh
./mysh -c 'echo hello | cat'
./mysh < commands.txt
./mysh --dump-tokens -c 'echo "hello world" > out'
./mysh --dump-ast -c '(echo a; echo b) | cat && echo done'
```

Интерактивное приглашение — `mysh$ `, продолжение кавычек/строки — `> `.
`Ctrl-C` прерывает переднее задание, `Ctrl-Z` останавливает его, `Ctrl-D` завершает
чтение. `help` показывает встроенные команды.

## Демонстрация для защиты

```sh
echo 'one two' | wc -w
echo first > demo.txt; echo second >> demo.txt; cat < demo.txt
false && echo skipped || echo recovered
pwd; (cd /; pwd); pwd
(echo a; echo b) | cat
sleep 30 &
jobs
fg %1
```

После последней команды нажмите `Ctrl-Z`, затем выполните `jobs`, `bg %+`,
`kill -TERM %+`, `wait`. Файлы примеров создавайте в отдельном рабочем каталоге.

## Проверка

```sh
make test
sh tests/check_memory.sh
make debug CC=gcc
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 make test
make clean
```

`make test` собирает `tests/test_shell.c` и запускает функциональные проверки
и пять сценариев с псевдотерминалом. Вывод: `PASS`/`FAIL` для каждой проверки
и `OK: 0 failed checks` при успехе; при ошибке возвращается ненулевой код.
Тесты работают во временном каталоге и удаляют созданные файлы.
Valgrind нужно запускать на обычной сборке, не поверх ASan.
GitHub Actions выполняет сборки GCC/Clang с `-Werror`, тесты и обе проверки памяти.

## Состав

| Путь | Назначение |
|---|---|
| `src/lexer.c`, `lexer.h` | Токены, кавычки, экранирование, комментарии |
| `src/parser.c`, `parser.h` | Рекурсивный спуск, AST, отладочный вывод |
| `src/exec.c`, `exec.h` | Процессы, конвейеры, списки, подоболочки |
| `src/redir.c`, `redir.h` | Перенаправления и восстановление дескрипторов |
| `src/builtins.c`, `builtins.h` | Десять встроенных команд |
| `src/jobs.c`, `jobs.h` | Группы процессов, состояния и терминал |
| `src/signals.c`, `signals.h` | Настройка сигналов и флаги обработчиков |
| `src/main.c` | Аргументы запуска и цикл чтения |
| `src/util.c`, `util.h` | Выделение памяти и диагностика |
| `tests/` | Функциональные, терминальные и ресурсные проверки |
| `report.md` | Отчёт, матрица требований, ограничения |

## История Git и публикация

В комплекте есть `mysh-history.bundle` — реальная история нескольких этапов
подготовки исходной версии проекта (файл лежит на уровень выше `mysh/`).
Она уже восстановлена в локальный `.git`; текущие доработки видны через `git diff`.
Это история исходного проекта, а не подтверждение самостоятельной разработки
автором отчёта. В отдельный каталог её можно восстановить без сервера:

```sh
git clone ../mysh-history.bundle mysh-repository
cd mysh-repository
git log --oneline
```

Удалённый репозиторий пока не создан. Чтобы выполнить соответствующий пункт ТЗ,
создайте пустой репозиторий в своём GitHub/GitLab и отправьте историю:

```sh
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

`YOUR_REPOSITORY_URL` нужно заменить адресом своего репозитория. Не создавайте
README на сервере перед первой отправкой, чтобы не получить две независимые истории.
