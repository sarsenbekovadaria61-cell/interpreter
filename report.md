# Курсовая работа

**Тема:** разработка командного интерпретатора UNIX/Linux на языке C.

**Выполнила:** Сарсенбекова Дария, студентка КФМГУ, 2 курс, ВМК.

**Основание:** «ТЗ семестрового проекта по разработке командного интерпретатора
(shell) v0.1». Имя программы — `mysh`. Год — 2026.

## 1. Цель работы

Разработать учебный интерпретатор, самостоятельно выполняющий лексический и
синтаксический анализ команд, построение AST и запуск процессов средствами POSIX.
Эталон для поддерживаемого подмножества команд — bash. Программа использует
стандартную библиотеку C и POSIX, без сторонних библиотек и внешнего shell для
разбора пользовательского ввода.

## 2. Реализованная базовая часть

- Лексика: слова, комментарии в начале слова, операторы `|`, `&`, `;`, `&&`,
  `||`, `(`, `)`, `<`, `>`, `>>`; выбор самого длинного оператора.
- Кавычки: одинарные и двойные, склеивание фрагментов слова, пустые аргументы,
  удаление кавычек, экранирование и продолжение строки через обратную косую черту.
  В двойных кавычках специальны только экранированные кавычка, обратная косая
  черта и перевод строки; `$HOME` остаётся буквальным текстом, как предписано ТЗ.
- Рекурсивный синтаксический анализ всей логической строки до начала выполнения.
  При ошибке ни одна команда этой строки не выполняется.
- Внешние команды: `fork`, поиск по `PATH`, `execve`, наследование окружения,
  ожидание через `waitpid`. Коды: 126 для невозможности исполнения, 127 для
  отсутствующей команды, `128 + N` при завершении сигналом.
- Перенаправления `<`, `>`, `>>` в любой позиции, слева направо, создание с
  правами `0666` с учётом `umask`. Ошибка открытия возвращает 1.
  Для встроенных команд исходные дескрипторы сохраняются и восстанавливаются.
- Параллельные конвейеры из нескольких команд; закрытие неиспользуемых концов
  каналов; код последней команды; встроенные команды в дочерних процессах.
- Последовательности `;`, фон `&`, короткое замыкание `&&` и `||` с одинаковым
  приоритетом и левой ассоциативностью.
- Вложенные подоболочки, изоляция смены каталога, перенаправление списка целиком
  и участие подоболочки в конвейере.
- Встроенные команды: `cd`, `pwd`, `echo`, `help`, `exit`, `jobs`, `fg`, `bg`,
  `kill`, `wait`. `cd` без аргумента использует `HOME`; `echo` поддерживает `-n`.
  `exit` использует последний статус или указанный код по модулю 256 и
  предупреждает при первой попытке выхода с остановленными заданиями.
- Управление заданиями: группы процессов, передача терминала, состояния
  Running/Stopped/Done, маркеры текущего и предыдущего заданий, переиспользование
  номеров, спецификаторы `%n`, `%+`, `%-`, продолжение и отправка сигналов группе.
- Интерактивный ввод, `-c`, чтение stdin из файла/канала; в неинтерактивном
  режиме нет приглашения и передачи терминала, `fg`/`bg` возвращают ошибку,
  фоновые команды и `wait` доступны.
- Отладочные режимы `--dump-tokens` и `--dump-ast`.

Дополнительные задания не реализованы: в исходном ТЗ они не определены.

## 3. Архитектура

`main.c` разбирает параметры запуска и организует последовательность
«ввод → лексер → парсер → AST → исполнитель → новый ввод».
Основной цикл написан как `for (;;)`: после обычной команды, пустой строки,
ошибки запуска или интерактивной синтаксической ошибки начинается новая итерация.
Выход выполняется явно по `exit`, EOF, ошибке ввода либо синтаксической ошибке
в неинтерактивном режиме. Режим `-c` выполняет одну переданную строку.
Таким образом, бесконечный цикл не означает игнорирование предусмотренного ТЗ выхода.

`lexer.c/.h` формирует поток токенов и удаляет кавычки. `parser.c/.h` реализует
рекурсивный спуск по уровням list, and_or, pipeline, command и строит явное дерево.
Узлы SIMPLE, SUBSHELL, PIPE, AND, OR, LIST и ASYNC содержат дочерние узлы,
массив аргументов и список перенаправлений. Исполнение во время разбора отсутствует.

`exec.c/.h` обходит дерево и создаёт процессы; `redir.c/.h` управляет
дескрипторами; `builtins.c/.h` реализует встроенные команды; `jobs.c/.h`
инкапсулирует таблицу заданий; `signals.c/.h` настраивает сигналы;
`util.c/.h` содержит выделение памяти и диагностику.

## 4. Модель исполнения и задания

Задание хранит номер, PGID, подпись, массив процессов с PID и статусами,
признак фонового выполнения, порядок выбора текущего задания и настройки терминала.
Один конвейер — одно задание. PGID равен PID первого процесса. `setpgid`
вызывается с обеих сторон `fork`, устраняя зависимость от порядка планирования.
Служебный канал удерживает дочерние процессы до создания группы и передачи терминала.

Для фонового составного списка создаётся процесс, исполняющий его AST;
вложенные процессы наследуют группу этого задания. Передние задания ожидаются
через `waitpid` с `WUNTRACED`, продолжения учитываются через `WCONTINUED`.
После остановки или завершения терминал возвращается группе интерпретатора,
восстанавливаются его настройки. `fg` передаёт терминал и отправляет `SIGCONT`,
`bg` отправляет `SIGCONT` без передачи терминала.

Обработчик `SIGCHLD` только устанавливает `volatile sig_atomic_t` и сохраняет
`errno`; сбор статусов выполняется в обычном потоке через неблокирующий `waitpid`.
Уведомления печатаются перед очередным приглашением. Дочерние процессы
восстанавливают стандартные действия сигналов. При Ctrl-C на пустом приглашении
обработчик пробуждает ввод и позволяет вывести новое приглашение.
Из дочернего процесса при ошибке исполнения выполняется `_exit`, а не возврат
в цикл чтения родителя. При завершении shell оставшиеся задания принудительно
завершаются и собираются, память таблицы и дескрипторы освобождаются.

## 5. Сборка и запуск

Нужны Linux/WSL, GNU Make, GCC с C23 (например, GCC 14+) или современный Clang.
Из каталога проекта:

```sh
make CC=gcc
./mysh
./mysh -c 'echo hello | cat'
./mysh < commands.txt
./mysh --dump-tokens -c 'echo "hello world" > out'
./mysh --dump-ast -c '(echo a; echo b) | cat'
make test
make debug CC=gcc
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 make test
make clean
make CC=clang
sh tests/check_memory.sh
```

Makefile задаёт C23, `-Wall -Wextra`, `_POSIX_C_SOURCE=200809L` и цели
`all`, `debug`, `clean`. `debug` включает `-g` и ASan/UBSan.
Проверку Valgrind запускают на обычной сборке, отдельно от ASan.

## 6. Проверка

Функциональные тесты сравнивают поддерживаемые команды с bash, проверяют
перенаправления, большие конвейеры, коды возврата, фон и ожидание, атомарность
синтаксической ошибки, продолжение строк и стабильность числа дескрипторов.
PTY-тесты проверяют настоящие терминальные сигналы, остановку конвейера,
`bg`/`fg`, продолжение кавычек и восстановление после ошибки.
Отдельный тест проверяет повторное приглашение после нескольких команд и ошибок.
Весь набор реализован на C23 в `tests/test_shell.c`, без Python.
Запуск команд выполняется через `fork`/`exec`, вывод и ошибки захватываются
во временные файлы, коды завершения читаются через `waitpid`.
Терминальные сценарии используют `forkpty` из системной `libutil`, `poll`
и управляющие символы Ctrl-C/Ctrl-Z. Проверки имеют ограничение времени 8 секунд.
Для контроля дескрипторов тестовая программа сама запускается как внешняя
команда в режиме `--count-fds` и читает `/proc/self/fd`.

Проверено 6 ноября 2026 года в Ubuntu WSL, GCC 15.2.0 и Clang 21: сборка C23 с
`-Wall -Wextra -Wpedantic -Werror` без предупреждений; функциональные проверки
и пять терминальных сценариев на C пройдены для обоих компиляторов.
Новый C-набор также пройден на сборке shell с GCC ASan/UBSan и
`detect_leaks=1:halt_on_error=1`.
Valgrind 3.26.0 (`--leak-check=full --track-fds=yes`) завершил ресурсный сценарий
с 0 ошибками и 0 потерянными блоками. В родителе освобождены все блоки;
в дочерней подоболочке остаётся доступный снимок AST после `fork`, освобождаемый
ОС при `_exit` (1083 байта still reachable, не потерянная память).
После явного закрытия стандартных дескрипторов при выходе Valgrind показывает
только два унаследованных дескриптора среды запуска, без новых открытых дескрипторов.
При проверке исправлена задержка вывода встроенных команд перед `wait`:
после выполнения теперь явно сбрасывается буфер stdout.

## 7. Отличия и ограничения

Подстановки, переменные, шаблоны, here-doc, явные номера дескрипторов,
управляющие конструкции, функции, alias и сторонние встроенные команды
не входят в базу и отвергаются диагностикой. В кавычках такие символы могут
передаваться буквально. `cd -` и раскрытие `~` не поддерживаются.
Файл скрипта как аргумент не принимается; используйте перенаправление stdin.
Глубина вложенности при разборе ограничена 256 уровнями.

Осознанные отличия от bash: двойные кавычки не выполняют подстановки согласно
ТЗ; файл без допустимого формата не передаётся внешнему shell (код 126);
при выходе оставшиеся фоновые задания принудительно завершаются.
Подпись задания восстанавливается из AST, поэтому пробелы и кавычки могут
отличаться от первоначального ввода при сохранении смысла команды.
SIGINT в приглашении обрабатывается для перерисовки вместо буквального SIG_IGN,
при этом сам интерпретатор не завершается. Эти решения описаны явно;
согласование отклонений с преподавателем этим отчётом не подменяется.

Полное отсутствие дефектов для любых входов не заявляется. Все результаты
относятся к выполненным тестам. Нативная Windows-сборка не предусмотрена POSIX-ТЗ.

## 9. Заключение

Получен модульный учебный shell с самостоятельным разбором команд, процессами,

интерпретатор к чтению следующей команды после каждой завершённой итерации.
